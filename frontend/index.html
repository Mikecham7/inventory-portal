Help & FAQ

Answers to common questions about your inventory portal.

How do I personalize my client logo and brand color?

Open Settings → Client website & branding. Enter your public Client Website URL and select Fetch website branding. The portal looks for logo images, Apple touch icons or Open Graph images, plus primary brand CSS colors, supported storefront theme settings and theme-color metadata. Up to two public stylesheets, including CDN-hosted theme files, may be inspected; site scripts are never executed.

Review the results, paste a different public logo image URL or a hex color such as #2463EB if needed, and select Save branding. Fetching alone never changes saved branding. Missing metadata or blocked websites show a message and do not prevent manual entry. Blank logo/color fields restore ECL defaults. This does not require an API connection and does not connect your store or sync products.

Clients can edit only their own branding. Administrators and warehouse staff can edit the selected client's branding. Changes apply to the dashboard header and active navigation/buttons with contrasting text. Image palettes are not analyzed; CSS/theme metadata provides the automatic color suggestion.

What can each portal role access?

Administrators can switch client accounts, manage client configuration and staff, and access billing and system settings.

Warehouse staff can switch accounts for receiving, barcode check-in, inspection, fulfillment updates and activity logs. In Updates, choose Scan Barcode, center one barcode in the green target and hold steady. A highlighted message and a beep (when audio is available) confirm capture. Close camera or press Escape to release the camera; leaving Updates or hiding the page also stops it. Administrators and warehouse staff can add inventory even when an account is view-only for its client. Staff Settings contains client branding only; warehouse staff cannot access billing, master settings, staff management or store credentials.

Clients can access only their own inventory, inbound shipments, tracking, chat and activity. Item editing still follows their account's inventory permissions. Clients can maintain their own packaging notes and optional store configuration; billing is available only when shared by an administrator. The API enforces account boundaries as well as hiding restricted controls.

Store integrations: optional setup guide for Shopify, WooCommerce, BigCommerce, Amazon, Wix and custom stores

Beta (testing): Store integration settings are still being tested and may change. Automatic order sync is not enabled.

Choose how you want to work

API integration is completely optional. You can manage everything manually, use public URL product imports, or prepare API configuration for a future integration. No subscription to an API service or store token is required for manual entry.

  1. Manual: open Add item, type the product details, quantities, image URL and bundle information, then save. Double-click an inventory row to edit it later, subject to your account permissions.
  2. Public product URL or feed: open Add item → Sync from Website URL, paste a public product page, store homepage or JSON/RSS feed, and select Fetch details. Select one product, prefill, review and save. Imports support public Open Graph/JSON product metadata; supported Shopify homepages can discover a public products feed. Login-only pages, blocked sites or missing metadata may require a direct feed URL or manual entry.
  3. Optional API configuration: open Settings, choose a platform and enter your store address. Credentials are optional. Saving configuration alone does not validate keys, fetch orders, schedule synchronization or activate webhooks.

Before generating credentials

  • Use a store-owner account or ask your authorized store administrator. Never send tokens through portal Chat, email, screenshots, public feeds or URL query parameters.
  • Coordinate the required data and permissions with ECL first. Prefer read-only product/order access; do not grant write or broad customer access unless a separately approved integration requires it.
  • If Settings says encrypted storage is unavailable, save only your domain. ECL must configure its encryption key before you enter credentials. Stored tokens are never returned to the browser or exposed in profiles.

Shopify: create an app and obtain an access token

  1. Find the permanent your-store.myshopify.com domain in your Shopify store settings. Use this in portal Settings, rather than a storefront custom domain.
  2. With your store administrator/developer, open the Shopify Dev Dashboard, create an app, and configure a version with the minimum agreed Admin API scopes (for example read_products or read_orders). Order/customer data can require additional Shopify approval.
  3. Release the app version and install the app on the intended store. Approve only the required scopes.
  4. For an app and store belonging to the same Shopify organization, a developer can obtain a token server-side using the client credentials grant. The Client ID and Client secret are under the app's Settings in the Dev Dashboard. Exchange them with Shopify's token endpoint on the server; do not put the Client secret in this portal's Access token field.
  5. New Dev Dashboard apps do not show an Admin API token to copy from Shopify admin. Client-credentials tokens expire after about 24 hours and require renewal. An app for another merchant needs the appropriate Shopify authorization/install flow, not this same-organization grant. This portal does not implement token exchange, OAuth or automatic renewal.
  6. Only if you already have an appropriate Admin API access token, paste it into Settings → Shopify → Admin API access token. If you have an older custom app with an existing valid token, it may be used for configuration. Select Save configuration and keep a secure copy.

Follow Shopify's current token setup guide and Dev Dashboard app guide. Store interfaces and eligibility can vary; involve your developer if the options differ.

WooCommerce: generate a Consumer Key and Secret

  1. In WordPress, go to Settings → Permalinks and choose a format other than Plain. Ensure your store uses HTTPS.
  2. Go to WooCommerce → Settings → Advanced → REST API. Choose Add Key / Create an API key.
  3. Use a recognizable description, such as ECL optional integration, and select an authorized WordPress user. Start with Read permissions for future product/order imports.
  4. Select Generate API Key. Copy the Consumer Key (ck_...) and Consumer Secret (cs_...) into a secure password manager. The secret is shown only once.
  5. In portal Settings, choose WooCommerce, enter the HTTPS store base address (including a WordPress subdirectory if applicable), and enter both credentials. Save configuration. Do not enter your WordPress password.

See the official WooCommerce REST API key guide.

BigCommerce, Amazon, Wix and Other / Custom Storefront

  1. In Settings, select the platform and enter its public HTTPS store address or storefront page. Use a URL without query parameters or fragments; you can keep a storefront path. For Amazon, use a public seller/storefront address, not a Seller Central login or authorization URL.
  2. Save the address alone if you do not need credentials. Manual management and public URL product sync remain supported for every platform; some sites restrict metadata access, so manual entry may be needed.
  3. Only if preparing a future integration with your developer, enter an optional API token/key and additional connection details. Examples include a BigCommerce store hash, Amazon seller/marketplace identifiers, Wix site ID, or a custom API endpoint. Platform-specific authorization and scopes must be arranged separately. Never enter your store login password.
  4. Save configuration. Optional connection details are encrypted like credentials, are never returned to the browser, and require server-side encrypted storage. Leave both optional fields blank to preserve existing values for the same platform/address. To replace them, re-enter all values you want retained; select Remove saved credentials to clear them.

Configuration only, still in development: these options do not activate API connectors, OAuth, token exchange, credential validation, webhook receivers or automatic order sync.

Webhooks: prepare only after a receiver is provisioned

This portal currently has no order webhook receiver and does not generate a webhook URL. A webhook URL is the receiving service's HTTPS endpoint, not your store URL or this portal's home page. Ask ECL for an approved, client-specific endpoint and signing-secret instructions when an automation service is actually available. Do not activate a webhook against a guessed URL.

  1. Agree with ECL which events and fields are needed, how SKUs/client accounts map, how duplicate deliveries are handled, and whether a test environment is available.
  2. Shopify: once ECL provides a working receiver, open Settings → Notifications → Webhooks in Shopify admin (where available), select Create webhook, choose the agreed order event and JSON format, paste the approved HTTPS URL, select the supported API version and save. Developer-managed apps may register subscriptions through Shopify's APIs instead.
  3. WooCommerce: open WooCommerce → Settings → Advanced → Webhooks → Add webhook. Set a name, agreed order topic, Delivery URL and a dedicated Secret. Keep it Paused until ECL is ready, then set Active and Save webhook. WooCommerce sends an initial ping when activated.
  4. Exchange webhook signing secrets only through an approved secure channel. The receiver must verify Shopify/WooCommerce signatures and bind each webhook to the correct client before accepting events. Do not paste a webhook signing secret into the API-token fields.
  5. Send a test event and have ECL confirm its receipt and mapping. Only then enable automated processing. Monitor delivery logs and failure alerts; webhook setup alone is not proof that orders are syncing.

Official instructions: Shopify webhooks and WooCommerce webhooks.

Change, remove or troubleshoot a connection

  • Blank token fields preserve saved credentials for the same platform/domain. Enter replacement credentials to rotate them. Changing the store requires replacement credentials or selecting Remove saved credentials.
  • Remove configuration deletes the portal's saved domain and encrypted credentials. It does not revoke tokens, uninstall apps or delete webhooks in your store; do those separately in Shopify/WooCommerce.
  • A saved-credentials indicator means encrypted data is stored, not that Shopify/WooCommerce accepted it. This configuration view does not test credentials or renew expired Shopify tokens.
  • For public URL imports that fail, try a single public product page or a smaller feed (up to 2 MB / 50 product choices), or continue manually. You do not need to configure an API connection to resolve this.
  • If you need assistance, message ECL with the platform and error description only, never the secret. Manual management remains fully supported before, during and after integration setup.
How do I notify ECL about incoming restock boxes?

All client accounts can use inbound restocks when enabled, even when inventory editing is restricted. Administrators can turn Enable Inbound Restock Shipments on or off when creating or editing an account; it is enabled by default. Select Notify Restock / Add Inbound Shipment on Dashboard or ECL Tracking. Enter the carrier, tracking number, expected delivery date and one product name/expected-quantity line per item. SKU and exact retailer product URLs are optional. Log one tracking number per shipment, then select Notify warehouse. Disabling the feature hides the section and blocks inbound actions without deleting existing shipment records.

The inbound section shows en-route and arrived shipments with their expected contents. ECL staff select the client account, focus the Dock scan field, scan the tracking barcode with a USB scanner and press Enter. Staff can also use a shipment's arrival button. If a number matches more than one record, use the button on the correct shipment.

Arrival records include the time and staff member. After arrival, a staff-only receiving popup shows each product, suggested inventory matches and an option to create a new inventory line. Staff confirm usable received, lost and damaged quantities totaling the expected amount. Only usable received units are added to stock (or Quantity Received for fulfillment accounts); lost and damaged units remain logged on the shipment. Arrival alone does not change quantities. Use Review received products to reopen the popup or retry a pending decision; do not manually add units after an uncertain save.

Amazon and eBay search links appear automatically in receiving reviews and inventory item details. Search results are not verified listings. An optional exact retailer URL can fetch product name, SKU and image for review; choose the correct result before applying it. Saving receiving or item details preserves the confirmed product listing URL. Public website restrictions still apply; manual entry remains supported. This log reflects ECL check-ins, not live carrier delivery events.

Only administrators can delete an inbound shipment. Select Delete shipment, enter a required reason and the administrator deletion PIN. The server must have ADMIN_DELETION_PIN privately configured; the browser-only protected-action PIN does not authorize deletion. Safe deletion reverses only that package's usable received stock and its product metadata, and removes newly created product lines only when they contain no other stock. Pending receipts, shipped/changed inventory, or older receipts without reversal snapshots require reconciliation first. The Inbound_Deletion_Audit sheet retains who requested deletion, when, why, the original shipment and the reversal plan. Deletion never erases that audit.

Where do I save packaging and prep instructions?

In Settings, choose Edit client packaging notes under Standard Operating Procedure / Packaging Notes. Saved notes appear read-only on Dashboard and apply to every item in your account; an empty notes section is not shown on Dashboard. Clients can maintain their own notes even if inventory is view-only; administrators can edit notes for the selected client. Optional API integration in Settings is still in development and may not work correctly.

For SKU-specific requirements, use Special Prep Instructions in Add item or the item detail/edit view, subject to normal item-editing permissions. Each field supports up to 5,000 characters.

ECL staff see client-wide rules and item instructions together during receiving/check-in, item inspection, and prep/packing updates, as well as ECL Tracking. Neither field replaces the other. Inbound restock cards show prep instructions for SKUs already present in inventory; unknown SKUs must be reviewed separately. Contact ECL if instructions conflict.

How do I add a new inventory item?

Open the Add item tab, enter the product title and starting quantity (the SKU is optional), fill in any extra fields for your account, then select Add.

If you don't see an Add item tab, your account is view-only or PIN-protected. Message the ECL team in Chat and they can add it for you.

How do I update quantities or shipment progress?

Open Updates, search for the item by SKU or product name, and select it. You can then:

  • Enter quantities received and shipped under Received & shipped.
  • Use + Add / − Remove for quick adjustments.
  • Open Set exact quantity to replace the on-hand count.

Some accounts ask for a PIN before changes can be made.

How do I find or filter items on my dashboard?

Type a SKU or product name in the dashboard search box — results update as you type. Select Filters to narrow the list by status, such as low stock or partially shipped.

How do I switch between dark mode and light mode?

Select the Dark mode or Light mode button in the top-right of the portal header. The portal updates right away and remembers your choice in this browser for your next visit.

What do the status labels mean?

In Stock, Low Stock, and Out of Stock describe items counted on hand. For shipment-tracked items, Not Received means nothing has arrived yet, Partially Shipped means some units have shipped out, and Fully Shipped means everything received has shipped.

Where can I see a history of changes?

Open the Activity tab. Each row shows the timestamp, action, user, and details, with the most recent first. Use the filter box to search any column; the list refreshes automatically while it's open.

How do I create my portal account?

Use the exact username and one-time account setup code provided by ECL. Select Create Account on the sign-in screen, choose a password, and save the recovery code shown. Select Continue to Your Inventory to open your inventory.

How do I reset or change my password?

Sign out, then select Forgot Password? on the sign-in screen. Enter your username, your recovery code, and a new password.

You'll receive a new recovery code afterwards — save it somewhere safe, because the old one stops working.

I lost my recovery code. What should I do?

Contact ECL through Chat, at eclsupport@electriccitylogistics.com, or at (406) 948-2719. We'll send you a one-time reset code to use in place of your recovery code on the Forgot Password? screen.

How do I contact the ECL team or share files?

Use the Chat tab to message the team directly. The chat page also links to your shared Drive folder for documents and labels. The bell icon at the top shows unread replies and inventory updates.

Where can I see my billing?

If billing is enabled for your account, the Billing tab shows this month's charges and an end-of-month estimate. If you don't see it, ask the ECL team to turn it on.

Why was I signed out?

For security, sessions expire after a set time. Sign in again to continue — your data is unaffected.
